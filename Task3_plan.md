# План по задаче №3 — AI-Recruiter

Мультиагентная система семантического ранжирования и скоринга кандидатов.

- Дедлайн: 27 сентября 23:59
- Формат: соло
- Заказчик: Бояджи Владислав

---

## 1. Цель (кратко)

Загружаем вакансию → векторный поиск отбирает топ-N кандидатов из базы резюме → команда LLM-агентов (Технический Скринер + HR-Аналитик) проводит построчный аудит → генерируется аналитическая карточка с процентом соответствия, плюсами/минусами/рисками и вердиктом «Рекомендован / В резерв / Отказ».

---

## 2. Стек (для соло — минимум движущихся частей)

| Слой | Выбор | Зачем |
|------|-------|-------|
| Парсинг PDF/DOCX | `pypdf` / `python-docx` | извлечение текста резюме |
| Чанкинг | свой сплиттер по секциям резюме | нарезка на смысловые фрагменты |
| Эмбеддинги | `sentence-transformers` + `intfloat/multilingual-e5-large` (или `BAAI/bge-m3`) | поддерживает русский + английский |
| Векторная БД | `ChromaDB` | локально, просто, без сервера |
| LLM | Ollama (`qwen2.5:14b` / `llama3.1`) ИЛИ облачный API (OpenAI-совместимый) | агенты; structured output через JSON |
| Оркестрация агентов | `LangGraph` ИЛИ простой Python-цикл с function calling | дебаты Скринер ↔ HR-Аналитик |
| Валидация структур | `Pydantic` | контракты JSON |
| UI (опционально) | Streamlit | демо-скринкаст |
| Тесты | `pytest` | unit-тесты тулов |

Решение: эмбеддинги локально (модель на CPU/GPU), LLM — через Ollama локально или облачный API. Оставить переключатель (конфиг), чтобы проверяющий мог запустить без GPU.

---

## 3. Архитектура (модули)

### 3.1 Parsing & Embedding Pipeline
- Извлечение текста из PDF/DOCX резюме и вакансий.
- Нормализация, чанкинг по секциям (опыт, навыки, образование).
- Индексация чанков в ChromaDB с метаданными (id кандидата, секция).

### 3.2 Tools Library (вызываются агентами)
- `semantic_search(vacancy_text, top_k)` — топ-K чанков по косинусному сходству.
- `extract_experience_years(resume_text)` — подсчёт коммерческого опыта по датам (регэксп/эвристика).
- `check_mandatory_skills(resume_text, skills)` — проверка стоп-слов/критичных навыков.
- `get_resume_chunks(candidate_id)` — догрузка доп. чанков из базы для уточнения.

### 3.3 Agent Orchestrator
- **Технический Скринер** — сопоставляет стек, хард-скиллы, масштаб проектов с требованиями вакансии.
- **HR-Аналитик** — оценивает динамику карьеры, софт-скиллы, частоту смены мест, red flags.
- Агенты могут вызывать тулы для уточнения деталей.
- Итог: структурированный JSON от каждого агента (Pydantic).

### 3.4 Report Generator
- Агрегирует выводы агентов, считает взвешенный скор соответствия.
- Формирует карточку кандидата (.md/.html): процент соответствия, Плюсы / Минусы / Риски, вердикт.
- Итоговая ранжированная выдача топ-кандидатов.

### 3.5 Данные
- Скрипт генерации демо-базы резюме (с фиксированным seed): ~100–300 резюме (PDF/DOCX).
- Набор тестовых вакансий (3–5 штук разной сложности).
- Воспроизводимый генератор, а не готовые файлы в репо.

---

## 4. Контракт данных

- Вакансия: JSON (`title`, `requirements`, `skills_must`, `skills_nice`, `seniority`).
- Чанк резюме: JSON (`candidate_id`, `section`, `text`, `embedding`).
- Результат агента: JSON (оценки по разделам, список плюсов/минусов/рисков, скор).
- Итоговая карточка: JSON + md/html (процент, вердикт, радар-текст).

## 7. Риски и защита (для соло)

| Риск | Защита |
|------|--------|
| LLM недоступна/нестабильна | Переключатель Ollama ↔ облачный API; fallback-скоринг без LLM (чистый векторный поиск) |
| Время не хватает соло | Держать минимальный скоуп: 2 агента, 1 векторная БД, отчёт в .md |
| Низкое качество LLM-объяснений | Structured output + Pydantic-валидация, дефолтные значения при ошибках |
| Проверяющий не может воспроизвести | requirements.txt + README с пошаговым запуском + фиксированные seed |
